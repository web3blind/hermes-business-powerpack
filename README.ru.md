# Business Powerpack для Hermes

Отдельный плагин. Gateway и Telegram-адаптер не изменяются. Сценария секретаря, автоподготовки ответов, кнопок подтверждения и перехвата следующего сообщения после «Изменить» нет.

## Что делает

- В личном чате владельца с Hermes публикует Telegram-истории через `/story` или инструмент `business_story` по обычному запросу. Инструмент также меняет подпись/медиа и удаляет только истории, зарегистрированные этим плагином.

- В явно выбранных Business-переписках распознаёт голосовые обеих сторон. Голосовое фактического владельца подключения, начинающееся после STT с «Гермес» или «Hermes», вызывает полноценного агента; в чат отправляется финальный ответ. Голосовое собеседника никогда не вызывает агента, даже с обращением; голосовое владельца без обращения тоже остаётся только расшифровкой.
- Владелец вызывает полноценный Hermes текстом в начале сообщения: `Гермес: запрос` или `Hermes запрос`. Если это ответ на сообщение в той же переписке, передаются имя отправителя и текст сообщения либо подпись к медиа (до 8000 символов). Цитата отделена от поручения и помечена недоверенными данными, не разрешением для инструментов. История всего чата не загружается. При явном запросе владельца вложение из reply (фото, изображение-файл, видео/видеосообщение, голосовое, аудио, анимация или документ) скачивается до 20 МиБ и передаётся агенту для анализа доступными инструментами. Файлы не исполняются, содержимое и названия остаются недоверенными данными. Поддержка чтения конкретного формата зависит от инструментов: зашифрованный или неизвестный формат может быть недоступен. Временный файл удаляется после запроса, в том числе при сбое. При ошибке скачивания агент не запускается, в чат отправляется безопасное объяснение. Чужое сообщение или вложение без явного вызова владельца не запускает анализ. Плагин запускает установленный CLI с обычными инструментами, моделью и штатными правилами approvals текущего профиля. Это не `ctx.llm` и не текстовый бот без инструментов.
- На каждую комбинацию home/bot/Business connection/chat создаётся отдельная именованная CLI-сессия. История основной переписки с Hermes не подмешивается.
- В чат отправляется только финальный результат из штатного stream-json. Промежуточные рассуждения, аргументы инструментов, логи и сведения о сессии не пересылаются.

## Границы доступа

Список чатов настраивается в профиле Telegram, в Business/Chat Automation. По умолчанию второй список в Hermes не нужен: обработчики получают только Business updates, которые Telegram разрешил передать этому боту. Это не доступ ко всем чатам аккаунта или истории.

`owner_ids` обязателен: пустой список отключает обработку, чужой владелец подключения отклоняется. При необходимости можно дополнительно сузить доступ через `allowed_chats`; отсутствующий ключ означает выбор Telegram, явный пустой список отключает все чаты. При обычной установке этот ключ не задаётся.

Владелец BusinessConnection должен совпасть с настроенным owner ID. Чужой обычный текст не вызывает инструменты. Голосовое допускается только от владельца конкретного подключения или собеседника этого приватного чата. Правки сообщений и эхо от бота не запускают повторную обработку.

Перед запуском инструментов и перед каждым фрагментом ответа проверяется свежий BusinessConnection и право `can_reply`. Отправка всегда содержит его точный `business_connection_id`; перехода на обычную отправку ботом при ошибке нет. Изменение подключения отменяет задачи. После ошибки отправки с неопределённым исходом автоматического повтора нет.

Запись обработки создаётся до выполнения. При повторе Telegram update, падении или перезапуске та же команда не выполняется снова. Новый осознанный запрос владельца — новое сообщение, а не повторный запуск старой записи.

## Ограничения текущей версии

- Вызов агента — явное обращение владельца в начале текста или расшифровки его голосового. Сопоставление строгое, без приблизительного распознавания имени; действуют те же настроенные triggers и границы слова (пробел, запятая, двоеточие). Telegram ID должен совпасть с фактическим владельцем свежего подключения; узнаваемость голоса не используется. Reply-контекст передаётся и для голосового вызова. Неявное «продолжай» не вызывает агента.
- Ответы — текст. Файлы, картинки и другие media-директивы из CLI не пересылаются: пользователь получает сообщение, что медиа не отправлено.
- Одновременно обрабатываются не более двух задач (настраивается), одна задача на Business-маршрут. Сообщение на занятом маршруте или при заполненной ёмкости пропускается; очереди и скрытого повторного выполнения нет.
- Ошибки обработки записываются статусом в private receipts DB; сырые ошибки не публикуются собеседнику. Ошибка не запускает автоматический повтор.
- CLI запускается headless. Штатные approvals не обходятся. Инструмент, требующий интерактивного подтверждения, может завершиться отказом/таймаутом; подтверждающих кнопок плагин не добавляет.
- Сессии изолированы по маршруту, но процесс агента действует в том же Hermes-профиле и с его инструментами. Это не sandbox, не отдельный аккаунт и не изоляция файловой системы. Приватные данные профиля не должны запрашиваться для публикации собеседнику.
- Выбор чатов в Telegram меняется без перезагрузки Hermes. Локальная привязка владельца и необязательный дополнительный список читаются при подключении обработчиков. Отзыв подключения отменяет активные задачи. Telegram не предоставляет боту метод чтения текущего списка выбранных чатов: входящие Business updates и проверка отправки сервером — граница доступа. Исключение отдельного чата не гарантирует отмену уже запущенного инструмента; для немедленной остановки всех задач отключи подключение бота.
- Linux: блокировки `fcntl`, завершение группы процесса. Голосовые до 10 MiB и 300 секунд по умолчанию. CLI до 300 секунд, native STT в отдельном процессе до 180 секунд. Таймаут и отзыв подключения завершают группу процесса; повторная отмена не освобождает файл, блокировку и ёмкость до окончания очистки.
- Текст длиннее лимита явно помечается как сокращённый. Обычная расшифровка передаётся с выключенной разметкой: `MEDIA:` и пути не исполняются. Явное голосовое поручение владельца после обращения, напротив, передаётся агенту как запрос к инструментам; действуют обычные ограничения доступа и approvals. Пустое поручение не запускается, поручение длиннее 16000 символов отклоняется.

## Установка

Требования: установленный Hermes с `register_telegram_handler` и `register_tool`, CLI с `--format stream-json` и именованными сессиями, python-telegram-bot 22.1–22.x, Pillow, ffmpeg/ffprobe с libx265; для голосовых — настроенный native STT.

Скопировать корневые `.py` и `plugin.yaml` в `<HERMES_HOME>/plugins/business-powerpack/`. Активировать только после проверки и отдельного решения владельца. Настройки в `config.yaml` меняются через штатный CLI Hermes, не через копирование чужого конфига.

Пример структуры настроек (ID здесь примеры, не реальные разрешения):

```yaml
plugins:
  entries:
    business-powerpack:
      owner_ids: [111111]

      triggers: [Hermes, Гермес]
      timeout: 300
      stt_timeout: 180
      max_concurrent: 2
      max_voice_bytes: 10485760
      max_voice_seconds: 300
      cli: hermes
```

Плагин настраивается под конкретный профиль. `cli` может быть абсолютным путём к доверенному исполняемому файлу. Не задавать shell-команды. Credentials разрешаются самим Hermes из своего home; токены не копируются в плагин.

## Истории

1. Подключить того же бота к своему Telegram Business-аккаунту и дать отдельное право `can_manage_stories`. Подключение должен выполнить сам владелец. Выбор Business-переписок не ограничивает истории: это отдельное право аккаунта.
2. В личку с Hermes отправить фото/видео с подписью `/story Текст истории`. Либо ответить на фото/видео сообщением `/story Текст истории`. Команда с медиа сразу запрашивает публикацию, без промежуточного черновика. `/story` без медиа показывает краткую инструкцию и ничего не публикует.
3. Для обычного запроса приложить медиа и написать: «Сделай историю с этим фото и подписью …». Описание инструмента направляет Hermes к `business_story`. При отсутствии материала агент должен запросить его, а не публиковать произвольный файл.
4. Для изменения/удаления использовать обычный запрос с ID, который вернул плагин. Можно отдельно менять подпись (включая её очистку) без повторного присылания медиа. Если меняется только медиа, прежняя подпись сохраняется. Инструмент `list` перечисляет зарегистрированные ID, а не подтверждает, какие истории сейчас видны в Telegram.

По умолчанию история на 24 часа; инструмент поддерживает 6/12/24/48 часов. Публикация на странице профиля и защита от пересылки явно выключены. Подпись — обычный текст, без HTML/Markdown. Фотография приводится к 1080×1920 с чёрными полями, без обрезания содержимого; видео до 60 секунд — к потоковому MP4/H.265 720×1280. Исходное локальное медиа до 40 МиБ; у облачного Telegram `getFile` отдельно действует ограничение на скачивание 20 МБ. Готовое фото до 10 МиБ, видео до 30 МиБ.

Авторизация инструмента — только ContextVars реального gateway (`telegram`, `dm`, точные user/chat/message ID), не переменные окружения и не аргументы модели. Cron, CLI, группы, Business CLI-переписки и чужие профили не публикуют истории этим инструментом. Перед каждым публичным действием проверяются настроенный владелец и свежие права Business connection, независимо от `can_reply`. Несколько подходящих подключений не выбираются наугад. Одновременно выполняется одна операция с историями на владельца; занятый запрос отклоняется.

Новый инструмент и его описание подхватываются новой сессией Hermes; активную историю диалога и её набор инструментов не переписываем. Отдельный нативный `/story`-обработчик подключается через штатный hot-rewire без рестарта gateway. Подарки, звёзды, финансовые операции и чтение чужих/старых историй не добавлены.

Далее владелец самостоятельно подключает бота к аккаунту через официальный Business/Secretary Mode, выбирает доступные чаты и права. Это отдельный этап, не часть разработки. Не подключать основной аккаунт автоматически.

## Данные и проверка

Плагин хранит квитанции обработки и fingerprints подключений в `<HERMES_HOME>/business-powerpack/receipts.sqlite3`, права 0600, каталог 0700. После проверки владельца и отправителя, до запуска инструментов, таблица `routes` сохраняет точную привязку route → bot ID, Business connection ID, chat ID, owner ID и ограниченную подпись собеседника. Квитанция связывает route с исходным message ID. Подпись — недоверенные данные для отображения, не адресат и не разрешение. `State.lookup_route(route, bot, owner)` проверяет профиль и точные идентификаторы; перед любой отправкой нужна отдельная свежая проверка прав. Привязка переживает сбой/перезапуск, но не разрешает автоматический повтор. Старые хеши без адресата не угадываются и не мигрируются в вымышленные маршруты. Native CLI сохраняет историю отдельных Business-сессий в собственной базе Hermes. Временные `.ogg` удаляются после STT. При аварийном завершении временный файл может остаться в private media-каталоге.

Для историй в той же базе добавлены таблицы отдельных квитанций и метаданных: владелец, бот, connection, story ID, подпись и путь подготовленного медиа. Подготовленные файлы остаются в private `business-powerpack/story-media` для последующего редактирования; автоматическая очистка архива не реализована. Файлы исходного скачивания и неиспользованные результаты подготовки удаляются. Только разрешённые image/video cache текущего профиля и private story-media; URL, произвольные пути, symlink-выход и плейлисты с внешними ссылками запрещены.

Квитанция публичного действия создаётся до отправки. Один входящий запрос не публикует историю повторно даже при повторном Telegram update, повторном tool call или неоднозначной сетевой ошибке. Неопределённый результат не выдаётся за подтверждённый; автоматического повтора нет. Bot API не предоставляет метод повторного чтения произвольной истории: post/edit проверяют возвращённый объект Story (ID и аккаунт), delete — ответ `True`. Живые публикации при разработке/тестировании не выполняются.

Тесты запускать из Hermes checkout через `scripts/run_tests.sh /absolute/project/tests`. Они используют synthetic Telegram updates и контролируемый transport/child, без реальных Telegram-сообщений и логина. Дополнительно проверен установленный native CLI: модель реально вызвала `terminal`, результат `BUSINESS_TOOL_OK`, вызов подтверждён в native session DB. Реальное BusinessConnection/доставка на основном аккаунте пока не проверены.

Реализация самостоятельная на публичном PluginContext API; поведение сверено с Powerpack recipient commit `b245abff25bb564a0239471adcaeb9d58593a7cf` и способом регистрации официального `hermes-telegram-business` commit `e905f3bc5eeaa5a9dab9bc5155601b3ebec75757`. Их секретарский сценарий и модификации ядра не копировались.
